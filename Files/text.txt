Hi Manu, thanks for the well-structured set of clarifying questions — it’s exactly the kind of pre-spec alignment I appreciate. Here are my detailed answers based on current priorities and the app’s direction:

⸻

1. Audio Format Priorities

• Core priority for optimization in MVP: FLAC and ALAC (lossless formats most common in audiophile libraries).
• Fully supported by default (using native iOS frameworks): MP3, M4A (AAC), and OGG — no need for additional optimization.
• Planned for Phase 2: DSD (up to DSD256), APE, WAV, AIFF, and other niche or high-resolution formats.
• Playback resolution target: Support up to 24-bit / 192kHz. Bit-perfect playback if DAC/hardware allows.

⸻

2. Hardware Integration

• Prioritize support for popular iOS-compatible USB DACs (e.g., iFi, Chord Mojo, AudioQuest DragonFly).
• Yes — implement automatic hardware detection, with visual confirmation in the UI when a DAC is connected.
• Bit-depth and sample rate switching should reflect hardware capabilities where possible.

⸻

3. Performance Tradeoffs

• Users should be able to choose performance mode:
	•	Balanced (default): High-quality + battery-efficient
	•	Maximum Quality: No compression, full waveform, high-res
	•	Battery Saver: Lower resolution, simplified visuals
• Waveform visualization:
	•	In Library view: show simplified waveform or static preview
	•	In Playback: detailed real-time waveform synced to audio

⸻

4. Metadata Handling

• Embedded tags take priority over folder structure or external metadata.
• Support online enrichment via MusicBrainz and Discogs in later phases.
• Manual metadata editing (ID3, cover art, tags) is important, but can be v1.1 unless scoped in.
• Conflicts: allow users to choose source or set global preference in settings.

⸻

5. UI/UX Priorities

• Default theme: Dark mode only in MVP — aligns with audiophile aesthetic, OLED efficiency, and minimalist UX.
• Customization options for player UI:
	•	Waveform display style
	•	Track info density (compact vs. expanded)
	•	Accent color picker (optional, subtle)
• MVP design should reflect offline + online dual-mode UX from the beginning.

⸻

6. Library Size Considerations

• Target support for large libraries: 100,000+ tracks or 2TB+ local storage.
• Focus MVP optimization on speed-first indexing and playback.
• Memory efficiency (lazy loading, on-demand metadata) should be considered for scalability.

⸻

7. Feature Prioritization

Top priority in MVP development should go to:
	1.	Playback Engine: gapless, bit-perfect where applicable, smooth waveform UI
	2.	Library Browsing: high-performance, searchable, fast load
	3.	Smart Playlists (basic rule system): auto-curated lists based on user preferences

Nice-to-have but not MVP-critical:
	•	Metadata editor
	•	Online sync integrations
	•	Advanced DSP/EQ

⸻

8. Dual Mode UX (Offline + Online)

• This is a high UX priority. The app must clearly distinguish between:
	•	Offline Library: locally stored files only
	•	Online Mode: streamed or synced content (from personal cloud or future APIs)
• Must support download manager, source indicators, and storage toggles.
• UX should adapt per mode: disable irrelevant options, show sync/download status, etc.

⸻
