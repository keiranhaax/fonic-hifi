# Prompt Templates

Here are proven prompt templates for common development and professional tasks. Choose the template that best fits your needs, then customize it with your specific details.

## Available Templates:

### 1. CODE REVIEW
```
Please review this [language] code for:
- Logic errors and bugs
- Performance issues
- Security vulnerabilities
- Code style and best practices
- Maintainability concerns

**Code to review:**
[paste your code here]

**Context:** [brief description of what the code does]

**Specific concerns:** [any particular areas you want focused attention on]

Please provide specific suggestions with examples where possible.
```

### 2. BUG ANALYSIS
```
I'm encountering a bug in my [language/framework] application. Help me debug it systematically.

**Problem:** [clear description of the issue]

**Expected behavior:** [what should happen]

**Actual behavior:** [what actually happens]

**Error messages:** [any error messages or logs]

**Code context:** [relevant code snippets]

**Environment:** [OS, language version, framework versions, etc.]

**Steps to reproduce:**
1. [step 1]
2. [step 2]
3. [etc.]

Please provide a systematic debugging approach and potential solutions.
```

### 3. FEATURE IMPLEMENTATION
```
I need to implement [feature name] in my [language/framework] project.

**Requirements:**
- [requirement 1]
- [requirement 2]
- [etc.]

**Constraints:**
- [constraint 1]
- [constraint 2]
- [etc.]

**Current architecture:** [brief description of your current setup]

**Integration points:** [what this feature needs to integrate with]

Please provide:
1. High-level implementation approach
2. Step-by-step implementation plan
3. Code examples for key components
4. Testing strategy
5. Potential challenges and solutions
```

### 4. DOCUMENTATION GENERATION
```
Create comprehensive documentation for [component/function/module].

**Code/Component:** [paste the code or describe the component]

**Target audience:** [developers, end-users, API consumers, etc.]

**Documentation type needed:** [API docs, user guide, technical specification, etc.]

Please include:
- Clear description of purpose and functionality
- Usage examples with code
- Parameter/option explanations
- Return value descriptions
- Error handling information
- Integration examples
```

### 5. TEST STRATEGY
```
Create a comprehensive testing strategy for [feature/component/application].

**What to test:** [description of the feature/component]

**Test types needed:** [unit, integration, e2e, performance, etc.]

**Testing framework:** [Jest, pytest, etc. or ask for recommendation]

**Critical paths:** [the most important functionality to test]

**Edge cases:** [any known edge cases or boundary conditions]

Please provide:
1. Test plan with priorities
2. Specific test cases with examples
3. Mock/fixture strategies
4. Automation recommendations
5. Coverage goals
```

### 6. PERFORMANCE OPTIMIZATION
```
Analyze and optimize the performance of my [language/framework] application.

**Performance issue:** [description of the problem - slow loading, memory usage, etc.]

**Current metrics:** [any performance measurements you have]

**Code/component:** [paste relevant code or describe the bottleneck]

**Environment:** [production specs, expected load, etc.]

**Constraints:** [any limitations on changes you can make]

Please provide:
1. Performance analysis
2. Specific optimization recommendations
3. Code examples for improvements
4. Measurement strategies
5. Expected impact assessment
```

### 7. ARCHITECTURE REVIEW
```
Review the architecture of my [type] application and suggest improvements.

**Current architecture:** [describe your current setup]

**Technology stack:** [languages, frameworks, databases, etc.]

**Scale requirements:** [users, data volume, etc.]

**Pain points:** [current problems you're experiencing]

**Goals:** [what you want to achieve - scalability, maintainability, performance, etc.]

Please analyze:
1. Current architecture strengths/weaknesses
2. Scalability concerns
3. Maintainability issues
4. Security considerations
5. Recommended improvements with rationale
```

### 8. API DESIGN
```
Design a [REST/GraphQL] API for [purpose/domain].

**Requirements:**
- [requirement 1]
- [requirement 2]
- [etc.]

**Data entities:** [describe the main data objects]

**Use cases:** [who will use this and how]

**Integration needs:** [what this API needs to connect with]

**Non-functional requirements:** [performance, security, etc.]

Please provide:
1. API specification with endpoints
2. Request/response examples
3. Error handling strategy
4. Authentication/authorization approach
5. Documentation structure
```

## Usage Instructions:

1. **Choose a template** that matches your task
2. **Copy the template** and replace bracketed placeholders with your specific information
3. **Customize as needed** - add or remove sections based on your requirements
4. **Be specific** - the more details you provide, the better the response
5. **Iterate** - use the initial response to refine your prompt and ask follow-up questions

## Pro Tips:

- **Combine templates** for complex tasks
- **Add examples** of what you're looking for
- **Specify output format** (markdown, code only, step-by-step, etc.)
- **Include context** about your skill level and project constraints
- **Ask for explanations** when you need to understand the reasoning behind suggestions
